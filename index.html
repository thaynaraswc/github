Como este guia funciona

São 8 passos em ordem. Pular um deles é a causa de quase todo erro que aparece no final — em especial o passo 3, onde a maioria das pessoas para no meio sem perceber.

Leia antes

Três tipos de aviso aparecem ao longo do caminho: Atenção (detalhe que costuma passar batido), Erro comum (o que quebra e por quê) e Confira (como saber que o passo deu certo antes de seguir).

  1. 1

    Prepare a pasta no seu computador

    Junte tudo o que a página usa em uma única pasta: o HTML, as imagens, e o CSS ou JS se estiverem em arquivos separados. Se você pediu o código a uma IA, peça o HTML completo e baixe também cada imagem citada — o link temporário de um chat some depois.

    • O arquivo principal tem que se chamar index.html, tudo em minúsculo. É o nome que qualquer servidor procura quando alguém abre o endereço raiz.
    • Nomes de arquivo sem espaço, sem acento e sem maiúsculas: use foto-capa.jpg, não Foto Capa.JPG.
    • Os caminhos dentro do HTML precisam ser relativos: <img src="foto-capa.jpg">. Se aparecer C:\Users\... ou /Users/..., a imagem só existe no seu computador.
    Atenção

    O servidor da Cloudflare roda Linux e diferencia maiúsculas de minúsculas. No Windows e no Mac, Foto.JPG e foto.jpg são o mesmo arquivo; no ar, são dois arquivos diferentes — e um deles não existe.

    Confira

    Dê dois cliques no index.html e abra no navegador. Tudo o que estiver quebrado aqui vai continuar quebrado depois de publicado — o deploy não conserta caminho errado.

  2. 2

    Crie a conta e o repositório no GitHub

    O GitHub é onde o código fica guardado. Um repositório é a pasta desse código lá dentro — e é ele que a Cloudflare vai ler.

    1. Acesse github.com e crie a conta (gratuita).
    2. No canto superior direito, clique em + e depois em New repository.
    3. Em Repository name, use um nome curto, sem espaço e sem acento: pagina-no-ar.
    4. Marque Public. Não há problema: só o código da página fica visível, e é o caminho mais simples.
    5. Clique em Create repository.
    Atenção

    A tela seguinte mostra instruções de git por HTTPS e SSH. Ignore tudo isso — neste guia o envio é pelo navegador, sem instalar nada. Nunca coloque senha, chave de API ou dado pessoal dentro dos arquivos: em repositório público, qualquer pessoa lê.

  3. 3

    Envie os arquivos e confirme o commit

    Este é o passo em que quase todo mundo tropeça. Enviar os arquivos e confirmar o envio são duas ações separadas no GitHub.

    1. Na tela do repositório, clique em uploading an existing file (ou Add file → Upload files).
    2. Abra sua pasta e arraste os arquivos de dentro dela — não a pasta inteira, não um .zip.
    3. Role até o fim da página e clique no botão verde Commit changes.
    Erro comum

    Parar depois de arrastar os arquivos. Sem clicar em Commit changes, nada foi gravado no repositório — e o deploy na Cloudflare falha com uma mensagem de que não há arquivos para publicar. Se isso acontecer, volte aqui, dê o commit e mande a Cloudflare tentar de novo (Retry deployment).

    Confira

    Recarregue a página inicial do repositório. Você precisa ver index.html na lista de arquivos, com a mensagem do commit ao lado. Se a lista estiver vazia ou só com o README.md, o commit não foi feito.

    Atenção

    O upload pelo navegador aceita até 100 arquivos por vez e 25 MB por arquivo. Imagem de celular costuma ter 5 a 10 MB: comprima antes, senão a página fica lenta para quem acessa.

  4. 4

    Crie o projeto na Cloudflare Pages

    A Cloudflare é quem entrega a página para o mundo. O plano gratuito já inclui HTTPS, CDN global e deploys ilimitados.

    1. Acesse dash.cloudflare.com e crie a conta.
    2. No menu lateral, procure por Workers & Pages e clique.
    3. Botão azul Create application → aba Pages → Connect to Git.
    4. Escolha GitHub e autorize com seu login do GitHub.
    5. Na tela de permissão, marque Only select repositories, escolha apenas o repositório que você criou e clique em Install & Authorize.
    Atenção

    Se depois a Cloudflare não listar seu repositório, é porque a permissão ficou restrita a outro. Corrija no GitHub em Settings → Applications → Cloudflare Pages → Configure, adicionando o repositório certo.

  5. 5

    Configure o deploy e publique

    Selecione seu repositório, clique em Begin setup e preencha exatamente assim — o site é estático, então não existe etapa de build:

    Project name
    pagina-no-ar — vira o endereço
    Production branch
    main
    Framework preset
    None
    Build command
    (deixe vazio)
    Build output directory
    / — a raiz

    Clique em Save and Deploy e aguarde. O log mostra Cloning repository, depois Success: Assets published.

    Erro comum

    Preencher Build command com algo como npm run build por hábito. Seu projeto não tem package.json, então o build falha na hora. Campo vazio é o correto para HTML puro.

    Atenção

    Se você subiu os arquivos dentro de uma subpasta no GitHub (ex.: site/index.html), o Build output directory precisa ser site, e não /. Se aparecer uma oferta de plano pago no fim, pode fechar em Maybe later.

  6. 6

    Abra a página no ar

    Terminado o deploy, a Cloudflare mostra o endereço nome-do-projeto.pages.dev. Clique nele.

    Confira

    A página carrega com cadeado de HTTPS e as imagens aparecem. Teste também no celular, com dados móveis em vez do Wi-Fi — assim você garante que está vendo a versão pública, e não um arquivo em cache da sua máquina.

    Atenção

    Erro 404 nos primeiros minutos costuma ser propagação, não defeito: espere de 1 a 5 minutos e recarregue com Ctrl+Shift+R (ou Cmd+Shift+R no Mac). Se persistir, é nome de arquivo ou pasta de saída — veja a tabela no fim.

  7. 7

    Ligue um domínio próprio (opcional)

    Para trocar pagina-no-ar.pages.dev por www.seusite.com.br, você precisa de um domínio registrado — no Brasil, em registro.br ou em qualquer registrador.

    1. No projeto, abra a aba Custom domains → Set up a domain.
    2. Digite o domínio e siga as instruções do painel.
    3. Se o domínio já estiver na Cloudflare, o registro CNAME é criado sozinho. Se estiver em outro lugar, copie o valor mostrado e cadastre o CNAME no painel do seu registrador.
    Atenção

    Mudança de DNS leva de alguns minutos a 24 horas para propagar, e o certificado HTTPS do domínio novo só é emitido depois disso. Erro de certificado nas primeiras horas é esperado. Cadastre as duas versões — com e sem www — para não deixar um dos endereços fora do ar.

  8. 8

    Atualize a página depois

    A partir daqui a Cloudflare fica observando o repositório. Você nunca mais mexe no painel dela para publicar uma mudança.

    1. No GitHub, edite o arquivo pelo ícone de lápis, ou envie a versão nova por Add file → Upload files.
    2. Clique em Commit changes.
    3. O deploy dispara sozinho e leva cerca de um minuto.
    Confira

    Se você alterou e a página parece igual, quase sempre é o cache do navegador: recarregue com Ctrl+Shift+R ou abra em aba anônima. Em Deployments você vê o histórico e pode voltar a uma versão anterior com Rollback quando alguma alteração quebrar o site.

Quando der errado

Os sete problemas que respondem por quase todos os travamentos, na ordem em que costumam aparecer.

Diagnóstico rápido — do sintoma à correção.
SintomaCausa provávelCorreção
Deploy falha logo no início Arquivos enviados mas sem commit — o repositório está vazio. Volte ao GitHub, clique em Commit changes e depois em Retry deployment.
404 na URL .pages.dev O arquivo não se chama index.html, ou está dentro de uma subpasta. Renomeie para index.html minúsculo, ou ajuste o Build output directory para o nome da subpasta.
Página abre em branco HTML incompleto, ou o conteúdo veio dentro de um bloco de código copiado do chat. Abra o arquivo local no navegador. Se quebrar lá, o problema é o HTML, não a hospedagem.
Imagens não aparecem Caminho absoluto do computador, ou diferença de maiúsculas no nome. Use caminho relativo e o nome idêntico ao do arquivo enviado, letra por letra.
Build falha na hora Framework preset ou Build command preenchidos num site estático. Em Settings → Builds & deployments: preset None e comando vazio.
Alterei e nada mudou Faltou o commit, ou é cache do navegador. Confira em Deployments se há deploy novo; recarregue com Ctrl+Shift+R.
Domínio próprio não abre DNS ainda propagando ou CNAME incorreto. Aguarde até 24h e confira o CNAME no registrador. Enquanto isso, o .pages.dev continua funcionando.

Checklist final

Marque conforme avança — o navegador guarda o progresso neste dispositivo.

Este guia é uma página estática — o próprio tipo de arquivo que você acabou de publicar. Se ele estiver no seu repositório com o nome index.html, a Cloudflare já o serve como está.

Não gostou da Cloudflare? O mesmo repositório funciona no GitHub Pages, na Vercel e na Netlify, com passos equivalentes. Se preferir servidor próprio ou VPS, basta copiar os arquivos para a pasta pública do servidor web.
